## Upload Boundary (2026-04-30)

Upload ограничен whitelist функцией:

_isUploadAllowedKey()

Любой ключ вне списка:
- не отправляется
- логируется
- не считается ошибкой

Это защищает систему от:
- legacy мусора
- прав доступа
- будущих багов

## v1.9.0 — UID-only payment storage

Ключи оплат:
- канон: `payments_<uid>`;
- `uid` обязателен для каждого абонента;
- ЛС может повторяться и не может быть storage-key для новых оплат.

Запрещено:
- `payments_<ЛС>` для абонента с UID;
- fallback на ЛС при неготовой Data;
- чтение ledger до `JKH_UI_STATE.data.status === "ready"`.

Legacy:
- старые `payments_<ЛС>` могут существовать только как исторический мусор/материал для отдельной миграции;
- автоматическое удаление legacy-ключей запрещено без отдельного подтверждения.
