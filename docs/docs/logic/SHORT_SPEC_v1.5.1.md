# SHORT_SPEC — ПАПАЖКХ

Версия: **v1.5.2-patch**

Краткое техническое задание для внешнего разработчика / Codex.

---

## 1. Суть системы

Система ведёт:
- абонентов;
- начисления;
- оплаты;
- задолженность;
- пеню;
- отчёты и судебные формы.

Приоритет:
- юридическая корректность;
- воспроизводимость расчётов;
- изоляция данных пользователей;
- одинаковые данные на всех устройствах одного owner.

---

## 2. Главные архитектурные правила

### 2.1. Owner
Все данные принадлежат конкретному пользователю (`owner`).

`owner`:
- определяется только сервером из сессии;
- не принимается от клиента как источник истины.

### 2.2. Источник истины
- backend / сервер — источник истины;
- localStorage — кэш и офлайн-копия.

### 2.3. Изоляция
Пользователь видит и изменяет только свою базу.

---

## 3. Ledger платежей

`payments_<LS>` — это помесячный ledger, а не просто список событий.

Правила:
- допускается несколько строк в одном месяце;
- `accruedYM = max(accrued)`;
- `paidYM = sum(paid)`;
- `debtYM = max(0, accruedYM - paidYM)`.

Оплата за период:
- влияет только на пеню;
- не меняет основной долг;
- не переписывает прошлые месяцы.

---

## 4. Тарифы

- тарифы задаются на уровне owner;
- у каждого пользователя своя база тарифов;
- тарифы применяются ко всем его абонентам;
- тарифы не принадлежат отдельному абоненту.

Права:
- admin — меняет;
- user — только смотрит.

---

## 5. Ставки рефинансирования

- ставки задаются на уровне owner;
- действуют для всех абонентов пользователя;
- изменять ставки может только администратор;
- user видит ставки только в read-only режиме.

Дополнительно:
- user может отправить сообщение об ошибке ставки;
- в будущем допускается серверное автообновление ставок из интернета с логированием и историей.

---

## 6. Импорт и расчёт

- Excel импортирует факты;
- импортные данные не должны тихо ломать расчёт;
- исключённые периоды отключают только пеню;
- мораторий меняет режим применения ставок, но не меняет сам долг.

---

## 7. Синхронизация

После входа и загрузки с сервера все устройства одного owner должны видеть одинаковые:
- тарифы;
- ставки;
- абонентов;
- связанные owner-данные.

Если это не так — синхронизация считается сломанной.

---

## 8. Что запрещено

Запрещено:
- хранить тарифы на уровне абонента;
- позволять user менять ставки рефинансирования;
- доверять owner из frontend;
- менять ставки автоматически на клиенте;
- менять ставку без истории и аудита.
