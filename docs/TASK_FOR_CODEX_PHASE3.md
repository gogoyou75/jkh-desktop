# TASK FOR CODEX — PHASE 3
## Тема: очистка миграции + migration flag + versioning ставок

---

## Контекст

В PHASE 2:
- введены canonical ключи:
  - tariffs_{owner}
  - ref_rates_{owner}
- убран dual-write
- добавлена миграция legacy → canonical

Но текущая реализация миграции:
- может создавать legacy ключи (например tariffs_content_repair_v1)
- не фиксирует факт завершения миграции
- не имеет versioning структуры для ставок

Это создаёт риск:
- лишних данных
- повторной миграции
- будущих несовместимостей структуры

1. Сделать **чистую одноразовую миграцию**
2. Исключить создание любых legacy ключей
3. Добавить **migration flag**
4. Добавить **version в структуру ставок**
5. Подготовить данные к будущим изменениям структуры

## 1. Миграция (КРИТИЧНО)

### Требуется:

Миграция должна быть строго:

legacy → canonical

### ❌ Запрещено:

- создавать новые legacy ключи
- сохранять данные в legacy после миграции
- использовать legacy как постоянный fallback
- делать dual-read или dual-write
